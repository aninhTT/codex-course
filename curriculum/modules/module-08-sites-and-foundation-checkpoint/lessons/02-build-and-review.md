# Lesson 8.02: Build the Site and improve one thing

Make the first version, try it, and give feedback based on what happens.

## Learn

A **saved version** preserves a Site candidate. A **deployment** makes a version live at a production URL. Ask to save without deploying while you review.

In Work or Codex, describe the website and use Sites when available. Focus feedback on what a reader sees or does. You do not need to inspect code to notice a confusing heading or broken filter.

Use sample information for the first build if audience access is still undecided. Save source details so later updates do not depend on guessing where the content came from.

## See It

“Build the website from our plan and save a version without deploying. Make the decision request easy to find on mobile and desktop.”

## Practice

Your tutor guides one step at a time in Work or Codex. Continue the recommended team-update example, or adapt the steps to your saved workflow choice.

1. Ask Sites to build the first version from your plan and reviewed content. Save without deploying.

2. Open the result on a wide and narrow layout. Try its links and interactions.

3. Identify one confusing or broken part. Ask for a focused change and try it again.

4. Save the reviewed candidate and record which source version it uses.

**Success criteria:** You built and inspected a Site candidate, then verified one improvement.

## Challenge — Optional

Ask the assistant to inspect the Site as a first-time visitor. Choose one useful suggestion and test it.

**Success criteria:** The change helps the reader complete the Site’s main job.

## Quick Check

What did the assistant assume? Which fact or behavior did you verify yourself?

## Carry Forward

Keep the reviewed candidate and the source version it uses.
