# Lesson 8.04: Deploy the reviewed version and check it

Make the version you reviewed live for the audience you chose.

## Learn

Every Sites deployment URL is production. Deploy the reviewed candidate deliberately, then open that URL to check the result.

For a course sample, owner-and-workspace-admin access is a useful first audience where available. For real team work, use the named audience you chose. A deployment and an invitation are separate actions.

Check the production page after deployment. If you want a teammate to review it, specify that person and their access. Do not claim another user can open it until you have evidence.

## See It

“Deploy this reviewed sample version with owner-and-workspace-admin access. Return the URL and audience setting, then help me inspect the live page.”

## Practice

Your tutor guides one step at a time in Work or Codex. Continue the recommended team-update example, or adapt the steps to your saved workflow choice.

1. Check the saved version and unresolved blockers. Confirm the audience you intend to use.

2. Ask the tutor to deploy that version with the chosen audience. Use a limited sample audience if this is only practice.

3. Open the production URL and test the content, links, interactions, and displayed period.

4. If you choose a reviewer, name the person and role before asking for an invitation. Otherwise record wider sharing as a future step.

**Success criteria:** You verified a deployed URL and its saved audience, or recorded a specific deployment blocker.

## Challenge — Optional

Have one intended reviewer test access and the main interaction. Make one improvement from their feedback.

**Success criteria:** Your review includes evidence from the intended audience, not only your owner account.

## Quick Check

What did the assistant assume? Which fact or behavior did you verify yourself?

## Carry Forward

Keep the deployed URL, audience setting, and live review results.
