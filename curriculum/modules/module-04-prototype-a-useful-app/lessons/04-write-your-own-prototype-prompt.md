# Lesson 4.04: Write Your Own Prototype Prompt

## Where You Are

You have seen Codex edit a prototype. Now you will write the prompt for what you want, using guiding questions instead of copying a finished prompt.

## Learn

The best prototype starts from a pain point in your professional life. Do not start with "build me an app" in the abstract. Start with the thing that slows you down, gets forgotten, is hard to review, or would be easier to understand visually.

Your prompt should answer:

- What pain point should this prototype help with?
- Who is it for?
- What should the first screen show?
- What 2 or 3 features matter for v1?
- What data can be fake or sample data for now?
- What should stay out of scope?
- How will you review whether it works?

For course work, keep the prototype in this course folder or `practice-workspace/`. If it becomes something you will keep using for real work, it can move into its own folder later.

## Practice

Write your own prompt in Codex. Use these guiding questions as your checklist, but use your own words:

```text
I want to build a small prototype that helps with [pain point].
The user is [who it is for].
The first screen should help them [job to be done].
For v1, include [2 or 3 features].
Use sample data for now.
Leave out [what is out of scope].
Before building, ask me any important clarifying questions and then help me make this prompt stronger.
```

**Success criteria:** The learner writes their own prototype prompt and understands what must stay small for v1.

## What You Made Or Decided

You drafted your own prototype prompt around a real pain point.
