# Lesson 10.03: Review the Goal and decide whether to run it

Challenge the instruction before asking the assistant to keep working toward it.

## Learn

Look for three common problems: a vague outcome, a finish line you cannot observe, or work with no sensible boundary. A polished Goal can still have all three.

Ask the tutor to explain the controls in your chosen desktop surface. Check how to pause, resume, edit, or clear the Goal before starting it.

Saving a strong draft is enough for this lesson. Start only when the sources and review time are ready. A web Work request can use the same outcome and evidence without assuming an identical Goal control.

## See It

“Review this Goal before I run it. Which requirement cannot be checked from the output? Which action goes beyond my intended scope?”

## Practice

Your tutor guides one step at a time in Work or Codex. Continue the recommended team-update example, or adapt the steps to your saved workflow choice.

1. Have the tutor critique your Goal and identify the most important weakness.

2. Revise it and compare the before-and-after wording.

3. Find the available controls in your chosen setup and explain how you would stop or redirect the work.

4. Choose to save the Goal or explicitly start it. Record whether you saved the draft or started the Goal, and where you will review the result.

**Success criteria:** You improved the Goal and know whether you saved it or started it.

## Challenge — Optional

Create a reusable Goal template with placeholders, an output sketch, and a note about when not to use it.

**Success criteria:** Someone could adapt the template without losing the verification requirement.

## Quick Check

What did the assistant assume? Which fact or behavior did you verify yourself?

## Carry Forward

Bring the reviewed Goal and its actual saved-or-running status.
