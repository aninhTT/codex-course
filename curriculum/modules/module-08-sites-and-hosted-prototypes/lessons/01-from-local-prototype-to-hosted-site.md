# Lesson 8.01: From Local Prototype To Hosted Site

## Learn

In Module 4, the goal was a local prototype you could inspect and improve. Sites adds a publishing path, but publishing is not the same as prototyping.

Before choosing Sites, compare simpler options. If people only need to read the output, a document may be enough. If they need rows, sorting, and recurring updates, a spreadsheet may be enough. If they need a shared interactive surface, a Site may be justified.

Think of the stages this way:

1. **Local preview:** useful for building and checking the experience on your machine.
2. **Saved version:** a reviewable candidate that is not automatically shared as a live production deployment.
3. **Deployment:** a production URL for a chosen audience.

The safest habit is to review locally first, save a version when you need a candidate, and deploy only when the audience and content are ready. In this module, you will deploy intentionally so you leave with a real Codex Sites URL.

## Practice

Try this in Codex:

```text
Review my Module 4 prototype or Module 6 Workflow Starter Kit and tell me whether this should stay a document, become a spreadsheet, remain a local prototype, or become a Site. Do not deploy yet. Explain what should be checked locally first, what would make a good saved version, and what would need to be true before final deployment later in this module.
```

**Success criteria:** The learner can explain the difference between local preview, saved version, and deployment.
