# Lesson 9.04: Build, preview, and inspect the changes

Let Codex build while you direct the result and test it.

## Learn

Codex can create and edit the app files from your plan. Its change view can help you see which files changed and what the edits contain.

Judge the app through the actual preview. Try each promised behavior, including an empty list or another simple edge case. A working happy path does not prove all inputs work.

Give feedback as expected behavior and observed behavior. That is more useful than saying the app feels wrong.

## See It

“The owner filter should show Maya’s tasks, but it still shows every row. Fix that behavior and show which files changed.”

## Practice

Your tutor guides one step at a time in Work or Codex. Continue the recommended team-update example, or adapt the steps to your saved workflow choice.

1. Ask Codex to build the approved plan in the selected folder.

2. Inspect the file changes and ask for a plain-language summary of the important edits.

3. Open the preview and try each feature. Record expected and observed behavior for one issue.

4. Request one focused fix, review its changes, and repeat the same check.

**Success criteria:** You built a local prototype, reviewed the changes, and verified a focused correction.

## Challenge — Optional

Ask Codex to review the app as a first-time user and fix one confusing interaction.

**Success criteria:** A repeated user task becomes clearer or more reliable.

## Quick Check

What did the assistant assume? Which fact or behavior did you verify yourself?

## Carry Forward

Keep the tested prototype, change review, and any known issues.
