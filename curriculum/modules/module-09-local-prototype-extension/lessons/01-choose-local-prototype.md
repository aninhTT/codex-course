# Lesson 9.01: Choose a small local tool to build in Codex

Explore the files behind a useful tool while keeping its first version small.

## Learn

A **prototype** is a working version used to test an idea. A **local prototype** uses files on your computer. We recommend Codex when you want to inspect those files and work directly with code changes.

This is an optional technical path. You can use Codex for the whole course, or move here from Work with your workflow brief. Your tutor can stay in either surface while guiding the Codex activity.

Use one screen and two or three features. The foundation Site is enough if you only need a shared hub. Choose a local tool when the file-level work will help you explore or maintain the idea.

## See It

A local decision-log prototype might add entries, filter sample decisions, and export a list. It does not need to recreate a complete project-management system.

## Practice

Your tutor guides one step at a time in Work or Codex. Continue the recommended team-update example, or adapt the steps to your saved workflow choice.

1. Extend the team-update example as a local dashboard, or use your saved workflow’s corresponding tool idea.

2. Open Codex for the build if you are currently in Work. Bring your brief, sources, and desired result.

3. Choose the course playground or a separate project folder and ask Codex to inspect it.

4. Describe one screen, up to three features, sample data, and how you will judge the result.

**Success criteria:** You have a small prototype purpose and a deliberate local project location.

## Challenge — Optional

Compare your local idea with a prompt-built Site. Explain why local file work is useful here.

**Success criteria:** The technical path serves the task rather than adding complexity for its own sake.

## Quick Check

What did the assistant assume? Which fact or behavior did you verify yourself?

## Carry Forward

Bring your prototype idea and chosen local project to the starter-app activity.
