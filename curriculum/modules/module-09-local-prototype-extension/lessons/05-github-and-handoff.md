# Lesson 9.05: Inspect GitHub and choose a handoff

See where code can live and decide what your prototype needs next.

## Learn

A **GitHub repository** holds project files and their change history. You used GitHub to retrieve Clean Draft; a code project uses it to track and collaborate on implementation too.

Codex can help inspect a repository and explain its files, history, and changes. You do not need to publish a repository or push code to understand this workflow.

Your prototype can stay local. If you want a hosted version, use the Sites review and deployment process from Module 8. A local file change does not update a deployed Site by itself.

## See It

“Read this repository and explain its purpose, main files, and how someone would run it. Do not change or publish anything.”

## Practice

Your tutor guides one step at a time in Work or Codex. Continue the recommended team-update example, or adapt the steps to your saved workflow choice.

1. Use the Clean Draft source repository or another repository you may access. Open it in GitHub with Codex’s help.

2. Ask Codex to explain its purpose and one relevant file or visible history entry. Keep this inspection read-only.

3. Write a handoff for your own prototype: purpose, folder, preview steps, checked behavior, and known issues.

4. Choose to keep it local, give it a separate maintained project, or plan a reviewed Sites deployment.

**Success criteria:** You inspected a real repository and saved a usable prototype handoff without an unintended publication.

## Challenge — Optional

In a repository you own, ask Codex to show a proposed change and explain how a commit would record it. Save or commit only if you choose.

**Success criteria:** You can connect a visible file change with its place in version history.

## Quick Check

What did the assistant assume? Which fact or behavior did you verify yourself?

## Carry Forward

Save the repository-inspection notes, prototype handoff, and hosting decision.
