# Lesson 5.04: Test the request and create the schedule

Run the exact request once, then save a schedule you can find and inspect.

## Learn

A manual test catches missing access and unclear instructions before a task repeats. Use the same request, sources, and environment you plan to schedule.

After creation, inspect the task in Scheduled. Check its next run, timezone, prompt, and output destination. Those saved settings—not a promise in chat—tell you what will happen.

You can create the task from Work or Codex in the desktop app. The tutor should carry out the supported setup steps when you request them. Account sign-in or a missing feature may need your attention.

## See It

“Test this request now. If it produces the expected draft, create the weekly schedule with the timing we chose and show me its saved settings.”

## Practice

Your tutor guides one step at a time in Work or Codex. Continue the recommended team-update example, or adapt the steps to your saved workflow choice.

1. Run your exact request manually. Open the draft and compare it with the sources.

2. Try a missing-input case. Check that it reports the problem without inventing an update.

3. Fix the request if needed, then ask the tutor to create the chosen weekly or monthly task.

4. Open Scheduled and verify the saved name, prompt, next run, timezone, and review destination.

**Success criteria:** You tested the request and verified a real saved schedule, or recorded the exact creation blocker.

## Challenge — Optional

Edit the timing of your practice task, verify the changed next run, then keep the timing you actually want.

**Success criteria:** You can modify an existing task without accidentally creating a duplicate.

## Quick Check

What did the assistant assume? Which fact or behavior did you verify yourself?

## Carry Forward

Keep the tested request and verified task settings, or the exact creation blocker.
