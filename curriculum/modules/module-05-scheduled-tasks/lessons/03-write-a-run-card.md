# Lesson 5.03: Write the request you will schedule

Write instructions that still make sense when you are not there to clarify them.

## Learn

A **durable request** says what to check, which period to use, what to produce, and what to do when information is missing.

Keep source notes separate from generated drafts. Otherwise a task can summarize its own previous output instead of new work. Tell it to report missing or stale inputs rather than producing a confident empty update.

Your tutor can save these choices in the run-card template. The card is a maintenance note, not a writing assignment. Historical course samples need an explicit test period; they are not current work notes.

## See It

“Each Friday, use weekly-update-helper on this week’s notes at [source]. Save a draft at [destination]. If the notes are missing or stale, report that instead. Do not send it.”

## Practice

Your tutor guides one step at a time in Work or Codex. Continue the recommended team-update example, or adapt the steps to your saved workflow choice.

1. Write your own recurring request using the skill, source, reporting period, and output location you chose.

2. Add the missing-input rule and choose whether the task should report “nothing new.”

3. Ask the tutor to review it as if running without you. Fix one ambiguity.

4. Have the tutor fill the run card with your choices, timing, reviewer, and pause instructions. Save it with your workflow.

**Success criteria:** The saved request specifies a method, current inputs, output, missing-input behavior, and a reviewer.

## Challenge — Optional

Read the request a month into the future. Replace any phrase that would depend on remembering today’s conversation.

**Success criteria:** The revised request has no unexplained “this,” “latest,” or “same as before.”

## Quick Check

What did the assistant assume? Which fact or behavior did you verify yourself?

## Carry Forward

Bring the saved recurring request and completed run card to the schedule test.
