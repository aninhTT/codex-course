# Lesson 3.01: Discover the skills you already have

Before building a new skill, find out which useful methods are already available.

## Learn

A **skill** saves a method for a recurring task. It can contain instructions, examples, references, and tools or scripts. A **plugin** can bundle skills and connections to services.

The assistant can choose a skill when your request matches its description. You can also select or name it. A description should explain when the skill applies, not simply say it is useful.

Skills do not grant access to every tool and do not schedule themselves. The skill defines the method. Connected tools provide access. A scheduled task supplies the timing.

We will use Clean Draft first, then build a method for the workflow you chose.

## See It

“Summarize these notes” is a one-time request. “Use our weekly-update skill” asks for a saved process with a consistent format and checks.

## Practice

Your tutor guides one step at a time in Work or Codex. Continue the recommended team-update example, or adapt the steps to your saved workflow choice.

1. Ask the assistant which installed skills are available for your current task. Request a one-sentence explanation for each relevant one.

2. Pick two. Ask which comes from a plugin and which tools or files it needs.

3. Try one appropriate installed skill on a small piece of work. Ask the assistant to identify the skill it used.

4. Explain the difference between the skill, a connected tool, and a schedule using that result.

**Success criteria:** You identified two useful skills and can distinguish a saved method from tool access and timing.

## Challenge — Optional

Describe a weekly task as a potential skill: inputs, method, output, and what would prove it worked.

**Success criteria:** Your description is narrow enough to test on one realistic input.

## Quick Check

What did the assistant assume? Which fact or behavior did you verify yourself?

## Carry Forward

Keep the skills you tried and your description of a repeatable task.
