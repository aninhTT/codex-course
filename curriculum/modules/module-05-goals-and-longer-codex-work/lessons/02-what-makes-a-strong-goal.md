# Lesson 5.02: What Makes A Strong Goal

## Where You Are

You know when a Goal is worth considering. Now you will learn the structure that keeps a Goal useful.

## Learn

A strong Goal gives Codex enough structure to keep moving without wandering. Think of it as a completion contract.

It should include:

- **Desired end state:** what should be true when the work is done
- **Verification evidence:** what Codex should inspect to prove the outcome
- **Constraints:** what must stay true while Codex works
- **Allowed inputs or boundaries:** which files, folders, tools, or sources Codex may use
- **Iteration policy:** how Codex should choose the next best action between attempts
- **Blocked stop condition:** when Codex should stop and explain what is missing

Template:

```text
/goal <desired end state> verified by <specific evidence> while preserving <constraints>. Use <allowed inputs, tools, or boundaries>. Between iterations, <how Codex should choose the next best action>. If blocked or no valid paths remain, <what Codex should report and what would unlock progress>.
```

Weak Goal:

```text
/goal Research competitors.
```

Stronger Goal:

```text
/goal Create an evidence-backed competitive market analysis of Thumbtack competitors, verified by a sourced report with global, national, local, large, and niche competitor categories, while preserving clear source links and uncertainty labels. Use approved web research, provided company notes, and any course-approved source list. Between iterations, expand the competitor map where evidence is thin and record why each source matters. If blocked or no defensible paths remain, report which competitor areas lack evidence and what source access would unlock progress.
```

## Practice

Try this in Codex:

```text
Teach me the Goal template in plain language. Then show me one strong Goal for a long audit, one for a competitive market analysis, and one for a large inbox cleanup or review queue. For each one, point out the desired end state, verification evidence, constraints, allowed inputs, iteration policy, and blocked condition.
```

**Success criteria:** The learner can identify the parts of a strong Goal and improve a weak Goal draft.
