# Lesson 5.03: Make A Rough Goal Better

## Where You Are

You know the Goal ingredients. Now you will practice upgrading a rough idea into a stronger Goal.

## Learn

Do not run the first Goal idea you write. Ask Codex to improve it first.

The most useful uplevel move is:

1. Describe the work in normal language.
2. Ask Codex to turn it into a stronger Goal.
3. Review the proposed Goal.
4. Tighten the evidence, constraints, boundaries, iteration policy, and blocked condition.
5. Decide whether to run it or save it for later.

Some learners will not have a good Goal use case yet. That is fine. The learning goal is knowing what the feature is for and how to draft one when the right task appears.

## Practice

Try this in Codex:

```text
Help me improve this rough Goal idea before I decide whether to run it: [paste a rough Goal idea here]. Use this template: /goal <desired end state> verified by <specific evidence> while preserving <constraints>. Use <allowed inputs, tools, or boundaries>. Between iterations, <how Codex should choose the next best action>. If blocked or no valid paths remain, <what Codex should report and what would unlock progress>. Ask only for details that are truly needed.
```

**Success criteria:** The learner practices turning a rough Goal into a stronger Goal without activating it.

## What You Made Or Decided

You improved a Goal draft and kept the decision to run it separate from the drafting step.
