# Lesson 4.03: Replay it with a different input

The useful test is whether the skill can repeat the method with new information.

## Learn

**Replay** means asking the assistant to use the captured skill for another task. Give it the values that are different this time.

Watch for fixed dates, fragile clicks, and save locations that only worked in the original demonstration. The assistant can use available computer, browser, or connected tools to follow the method.

Check the actual saved result. A success message is not enough if the report contains the wrong week or overwrote the original file.

## See It

“Use the capture skill for week 2. Save a new input copy, keep week 1 intact, and show the period in the result.”

## Practice

Your tutor guides one step at a time in Work or Codex. Continue the recommended team-update example, or adapt the steps to your saved workflow choice.

1. Review the captured skill and replace one fixed example value with a named input if needed.

2. Replay with week-02-notes.md so the current-input copy changes to week 2. For another chosen workflow, use its second input.

3. Open the result and check its period, name, contents, and location.

4. Fix a brittle instruction and replay that part again. Save the tested skill and result.

**Success criteria:** You replayed or walked through the captured method on a new input and checked the saved result.

## Challenge — Optional

Try an input that is missing a required field. Add a stop-and-report rule rather than a guess.

**Success criteria:** The skill identifies the missing input before performing the wrong action.

## Quick Check

What did the assistant assume? Which fact or behavior did you verify yourself?

## Carry Forward

Keep your tested capture skill and the new input it produced.
