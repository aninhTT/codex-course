# The Recommended Example: A Weekly Team Update

The course follows one recommended example from first draft to team Site. Use it if you want a ready-made path. If you have something else in mind, choose that instead and carry it through the same activities.

The important habit is continuity: use what you made in the previous module rather than starting an unrelated project each time.

## The Team-Update Story

You prepare a weekly update for team leads about a request-handoff checklist. They need progress, decisions, blockers, and next steps. The fictional notes leave some owners and dates unknown so you can practice preserving gaps.

| Module | Continue the same example |
| --- | --- |
| 1 | Make a short update draft. Connect tools, review your actual week, and decide whether this example fits your needs. |
| 2 | Create a Team Updates project, add week 1 notes and the update template, and save the original draft. |
| 3 | Run Clean Draft on that draft. Use Skill Creator to build weekly-update-helper. Test it with week 1, week 2, and missing notes. |
| 4 | Record preparing the current notes file. Replay with week 2, then pass that input to weekly-update-helper. |
| 5 | Schedule weekly-update-helper to prepare a Friday draft. Review the saved task and its next run. |
| 6 | Create a Team Update Page in a team-update space. Use the reviewed week 2 draft to update it. |
| 7 | Turn the reviewed update into a brief and three slides. Use the accompanying metrics for a checked spreadsheet. Choose the formats worth repeating. |
| 8 | Build a Team Update Hub Site from the reviewed content. Show the reporting period, progress, decisions, and next steps. |
| 9, optional | Build a local version of the team-update dashboard and inspect its files and changes in Codex. |
| 10, optional | Draft a Goal to audit the update's sources, copies, and missing review evidence. |

Clean Draft is the existing skill you learn from. The team-update skill is the new method you build, record a supporting step for, and schedule.

## Files and Handoffs

- Original sources: `practice-workspace/weekly-update/week-01-notes.md`, `week-02-notes.md`, `update-template.md`, and `sample-metrics.csv`.
- Recorded preparation step: open the chosen week's notes and save a new current-input copy. Use a separate input location, such as `practice-workspace/inputs/team-update/current-notes.md`.
- Drafts and cleaned versions: save separate files in `practice-workspace/outputs/` or the equivalent task files.
- Shared destinations: save the actual Page, work-file, and Site links in the output tracker.

Preserve the source files. The recording changes the input copy; it does not overwrite a draft or source. Keep input copies separate from generated updates.

The course notes are historical samples. Use their stated reporting periods for tests. A real recurring task needs fresh notes and a rule for missing or stale inputs.

The sample metrics show how many requests came in and how many were completed. They do not prove that the checklist caused a change in performance.

## If You Choose Something Else

Keep the same progression: original result → Clean Draft → custom skill → recorded supporting step → schedule → reviewed Page → useful files → Site.

A meeting brief, project summary, or research digest can work. Adapt the inputs, skill name, cadence, and destination with your tutor. Keep your choice in saved progress so each module builds on it.
